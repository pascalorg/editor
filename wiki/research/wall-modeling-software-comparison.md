# Architectural wall modeling software comparison

Research date: 2026-09-21

## Recommendation

Use Revit and Archicad as the primary references for a semantic wall model. Both make a wall a first-class building element with a reference path, inside/outside orientation, type-level construction, story or level constraints, hosted openings, material-aware junctions, quantities, classifications, renovation/design states, and multi-user ownership. AutoCAD Architecture is the strongest reference for explicit component-priority cleanup and drawing-based project partitioning. SketchUp and native Rhino are useful counterexamples: they are flexible geometric modelers whose native primitives do not impose wall semantics. Rhino.Inside.Revit and the Grasshopper–Archicad Live Connection show how a visual-parametric layer can drive native BIM walls without replacing the host application's wall schema.

For comparison with this repository, separate the problem into three layers:

1. **Wall intent:** reference path, orientation, height constraints, wall kind, assembly, classification, phase/option, and host relationships.
2. **Solved topology:** joined ends and intersections, component cleanup, openings, attachments, trims, and derived layer solids.
3. **Presentation and output:** detail-level graphics, materials, schedules, quantities, IFC mapping, and collaboration state.

This separation is more durable than treating a wall as only an extruded polygon, but it should still permit a free-form escape hatch for imported or exceptional geometry. The product survey below is based only on official vendor help, developer documentation, and vendor-owned materials. Vectorworks Architect is not included in this pass.

## Current repository audit

Pascal already has a genuine architectural wall object rather than anonymous geometry. The core schema stores an oriented start/end path, a circular-arc sagitta, thickness, explicit or storey-derived height, slab support, terrain fill, interior/exterior finish slots, decorative horizontal bands, and trim profiles. It explicitly hosts doors, windows, wall-mounted items, and lean-to extensions. See [`WallNode`](../../packages/core/src/schema/nodes/wall.ts) and the registered [`wallDefinition`](../../packages/nodes/src/wall/definition.ts).

The editing and topology behavior is one of the strongest parts of the implementation:

- placement works as a snapped continuous chain in both 2D and 3D;
- crossings split existing and new walls, including straight/arc intersections;
- endpoint moves propagate through junctions, while whole-wall moves can bridge or consume adjacent segments;
- level-wide footprint miters generate clean plan and model corners;
- hosted doors, windows, and attached items are remapped when a wall is split;
- doors, windows, and item cutout proxies produce real CSG openings; and
- plan output includes the mitered footprint, construction dimensions, hosted-opening dimensions, editable endpoints, thickness handles, and curve handles.

The wall also has useful vertical behavior: omitted height follows the storey plane, explicit height acts as an instance exception, a slab can establish the base, and `fillToTerrain` extends the base down without changing the authored top. These are meaningful advantages over native SketchUp and Rhino, where equivalent behavior must be modeled or scripted.

The important limitation is that Pascal still renders **one homogeneous wall solid**. Interior/exterior slots, horizontal face bands, skirting, crown, and chair rail are presentation finishes attached to that solid; they are not ordered construction layers. The schema has no reusable wall type/style, core boundaries, layer functions or priorities, reference-line choice, layer wrapping, structural role, thermal/fire/acoustic data, lifecycle state, or native classification/property-set contract. The floor plan consequently draws one filled footprint rather than a detail-level assembly section.

IFC import demonstrates the same reduction. `IFCWALL` and `IFCWALLSTANDARDCASE` are recovered as start/end, one height, one thickness, plus `ifcType`, `expressID`, and `globalId` metadata. Compound material layers, property sets, classifications, profiles, and construction behavior do not become native wall intent. See the [IFC wall conversion](../../packages/ifc-converter/src/index.ts).

|---|---|---|

## What Pascal is actually missing

### P0 — foundation before adding more wall shapes

1. **Reusable wall types/styles.** Instances should point to a shared definition instead of duplicating thickness and finish decisions. A type change must update every instance while preserving intentional instance overrides.
2. **Ordered compound assemblies.** Each layer needs material, thickness, function, core/finish role, join priority, and wrap policy. Total wall thickness should be derived from the assembly. This unlocks correct plan sections, quantities, IFC, and future energy analysis.
3. **A persistent reference/location line.** Support centerline, finish faces, core faces, and custom offset, with an explicit flip/orientation operation. Changing a wall type or thickness must not unexpectedly move the architectural face the user intended to hold.
4. **A real vertical constraint model.** Represent base/top level references and offsets, unconnected height, attachment to slabs/roofs/ceilings/terrain, and an editable elevation profile. The current `height`/storey fallback and terrain fill can become compatible modes inside this model.

These four concepts should be designed together. Adding compound layers without a reference line makes type changes unstable; adding layers without layer-aware joins creates visually and quantitatively incorrect corners.

### P1 — make the foundation behave like BIM

5. **Layer-aware cleanup and wrapping.** Resolve joins by component function/priority; let users choose butt/miter/square-off, join order, cap/disallow join, and cleanup groups where needed. Finish layers must wrap—or deliberately not wrap—at wall ends and hosted openings.
6. **Wall information and quantities.** Add mark/type mark, function, structural usage/load-bearing, room-bounding toggle, fire/acoustic/thermal properties, classification and IFC mapping. Derive gross/net length, area, and volume per wall and per layer, subtracting openings according to explicit rules. Build tags, schedules, and material takeoffs on those derived quantities.
7. **Richer parametric geometry.** Add slanted, tapered/double-slanted, variable-layer, edited-profile, stacked, and vertically compound walls. Expand placement with rectangle/polygon, ellipse, arbitrary curve/polycurve, room boundary, existing linework, and wall-by-face/solid workflows.
8. **Construction-detail presentation.** Plan, section, and elevation need detail levels, per-layer cut fills/hatches, core boundaries, opening closures, end caps, sweeps/reveals, and predictable symbolic output—not just one dark plan polygon.
9. **IFC round-trip.** Preserve wall types, material layer sets, property sets, classifications, placement/reference intent, profiles, opening relationships, and stable IDs on import; export native `IfcWall`/`IfcWallStandardCase` intent where representable and use an explicit geometry fallback otherwise.

### P2 — specialized systems and project lifecycle

10. **Curtain walls and panels.** Treat grids, panels, mullions, embedded doors, and manual overrides as a specialized envelope system sharing common wall identity where useful.
11. **Lifecycle and alternatives.** Add created/demolished phase or renovation status, design-option membership, and view/filter behavior. Element ownership/reservation matters only when real-time multi-user editing requires it.
12. **Free-form and visual-parametric bridge.** Keep imported/free-form solids as an escape hatch, and let procedural tools produce native wall intent where possible. Rhino/Grasshopper demonstrates why both paths are useful and why the editable native-wall path should remain the default.

### Recommended implementation sequence

1. Introduce `WallType` plus ordered `WallLayer` data and migrate the current single-thickness wall to a one-layer default type.
2. Add location-line semantics and make footprint/rendering derive layer offsets from it.
3. Extend the existing miter/topology solver to resolve layers, priorities, caps, and opening wrapping.
4. Replace the current height switch with base/top constraints, offsets, attachments, slant/taper, and elevation profiles.
5. Generate plan/section detail, net/gross/component quantities, schedules, tags, and IFC mappings from the same solved assembly.
6. Add stacked/curtain/free-form variants only after the shared type, constraint, join, and documentation contracts are stable.

A minimal direction for the domain model is:

```ts
type WallType = {
  id: string
  name: string
  layers: Array<{
    materialRef: string
    thickness: number
    function: 'structure' | 'substrate' | 'insulation' | 'finish' | 'membrane'
    core: boolean
    joinPriority: number
    wrap: 'none' | 'ends' | 'openings' | 'ends-and-openings'
  }>
}

type WallIntent = {
  wallTypeId: string
  locationLine: 'center' | 'finish-interior' | 'finish-exterior' | 'core-interior' | 'core-exterior'
  locationOffset?: number
  base: { reference: string; offset: number }
  top: { mode: 'level' | 'unconnected' | 'attached' | 'profile'; reference?: string; offset?: number }
  structuralUsage: 'non-bearing' | 'bearing' | 'shear' | 'combined'
  roomBounding: boolean
}
```

The main product recommendation is therefore: **do not prioritize curtain walls or exotic curves first. Build wall types, compound layers, location lines, and vertical constraints first.** Those are the dependencies that turn the current excellent editing object into a reliable BIM wall.

## Feature taxonomy

| Taxonomy area | Questions to ask |
|---|---|
| Identity and kind | Is a wall a domain object or generic geometry? Are basic, stacked, curtain, structural, and free-form walls distinct kinds? |
| Placement contract | What is authoritative: center/reference line, face, closed footprint, profile, or arbitrary solid? Which line, arc, ellipse, polyline, chain, room, face, and conversion modes exist? |
| Type versus instance | Which properties are shared by a type/style, and which may vary per wall? Can an instance override materials, display, geometry, or cleanup behavior? |
| Assembly | Are layers/skins ordered outside-to-inside? Do they carry thickness, function, core/finish role, material, wrapping, and join priority? Can construction vary vertically? |
| Vertical extent | Is the wall fixed-height, level/story-linked, top-linked, attached to another element, profiled, slanted, double-slanted, or tapered? |
| Connectivity | Are joins inferred from contact, represented explicitly, or grouped? Are butt/miter/square-off and component-level cleanup editable? Do edits remain associative? |
| Voids and hosts | Are doors/windows/openings true hosted children? Do they move with the wall, cut it, report quantities, and control layer wrapping? |
| Specialized envelopes | Are curtain walls, stacked walls, profile walls, sweeps/reveals, and mass/face-derived walls native variants or unrelated geometry? |
| Information and output | Can walls be classified, scheduled, quantified by component/material, filtered, tagged, exported to IFC, and round-tripped? |
| Lifecycle and collaboration | Are renovation/phases, design options, element ownership, worksets/reservations, and linked modules first-class? |
| Automation | Can APIs create and modify native walls, assemblies, inserts, joins, and quantities? Can graph-based tools retain native BIM identity? |

## Product notes

### Autodesk Revit 2027

Revit has the broadest single wall schema in this comparison. A wall is an instance of a predefined system-family type and is positioned by a Location Line; changing layer thickness or flipping the wall preserves that reference plane. Creation supports a line or measured segment, chains, sketched rectangles/polygons/circles/ellipses/arcs, existing lines and element edges, mass/generic-model faces, and newer place-by-segment/place-by-room finish workflows. Base level, top level or unconnected height, offsets, orientation, structural usage, and join status are instance decisions. [About walls](https://help.autodesk.com/cloudhelp/2027/ENU/Revit-ArchDesign/files/GUID-550F4B3E-7D49-4A4F-BEC7-4077D5B9FC85.htm), [Place a Wall](https://help.autodesk.com/cloudhelp/2027/ENU/Revit-ArchDesign/files/GUID-05BAFEAA-5186-484E-80F4-8D900C454748.htm)

Basic wall types own their outside-to-inside compound structure. Each layer has function and join priority, material, thickness, wrapping, and core membership; vertically compound walls subdivide layers into height regions. One variable layer enables a tapered cross-section, while instance cross-section can be vertical, slanted, or tapered. Stacked types vertically compose attached Basic subwalls. Elevation profiles, attached tops/bases, sweeps, reveals, embedded walls, and curtain walls expand the form vocabulary, although combinations have limits—for example slanted walls do not support miter or square-off joins, and arc-wall elevation profiles cannot be edited. [Compound walls](https://help.autodesk.com/cloudhelp/2027/ENU/Revit-ArchDesign/files/GUID-7657DF90-6AE2-4543-BFDA-7735A8424B1C.htm), [stacked walls](https://help.autodesk.com/cloudhelp/2027/ENU/Revit-ArchDesign/files/GUID-01A95335-C6A6-4759-A046-8E19BF872C67.htm), [slanted-wall limits](https://help.autodesk.com/cloudhelp/2027/ENU/Revit-ArchDesign/files/GUID-717C14D1-91E1-4A95-9DF6-1C46490F705C.htm), [profile/opening limits](https://help.autodesk.com/cloudhelp/2027/ENU/Revit-ArchDesign/files/GUID-672234E5-D6D4-44DE-9209-D0C12DF41992.htm)

Wall intersections are automatic but controllable: butt is default, with miter, square-off, join order, and don't-clean/disallow-join options. Layer function priorities determine component cleanup. Doors, windows, openings, and embedded walls are inserts of the host; compound finish layers may wrap at them. Curtain walls remain `Wall` elements but generate borders, grids, mullions, and panels from type and instance rules, with manual grid/panel overrides where needed. [Wall joins](https://help.autodesk.com/cloudhelp/2027/ENU/Revit-ArchDesign/files/GUID-19EAF7A9-331F-4271-94CC-43B76B13011E.htm), [compound structure](https://help.autodesk.com/cloudhelp/2027/ENU/Revit-Model/files/GUID-08E47F82-BFA1-4CAB-B2EA-6C8DC9049AD8.htm), [curtain-wall editing](https://help.autodesk.com/cloudhelp/2027/ENU/Revit-HaveYouTried/files/GUID-43DA0959-A541-459F-8370-C5149433FFB4.htm)

Walls participate fully in parameters, tags, wall schedules, material takeoffs, assembly codes, classifications, IFC mapping, project phases, design options, and worksharing. API clients can create walls from a base curve or closed planar vertical profile, inspect host inserts, and replace a wall type's compound structure. The official Rhino.Inside guide exposes those capabilities graphically but also records API boundaries: its current workflow cannot modify an existing wall's profile curves or create a new stacked-wall type. [Schedules](https://help.autodesk.com/cloudhelp/2027/ENU/Revit-DocumentPresent/files/GUID-F50D6FF4-859E-43A2-A2F6-81C84A1BA0EB.htm), [IFC setup](https://help.autodesk.com/cloudhelp/2027/ENU/Revit-DocumentPresent/files/GUID-E029E3AD-1639-4446-A935-C9796BC34C95.htm), [Revit API walls](https://help.autodesk.com/cloudhelp/2027/ENU/Revit-API/files/Revit_API_Developers_Guide/Revit_Geometric_Elements/Walls_Floors_Ceilings_Roofs_and_Openings/Revit_API_Revit_API_Developers_Guide_Revit_Geometric_Elements_Walls_Floors_Ceilings_Roofs_and_Openings_Walls_html.html), [Rhino.Inside walls](https://www.rhino3d.com/inside/revit/1.0/guides/revit-walls)

### AutoCAD Architecture 2027

AutoCAD Architecture's AEC Wall sits between drafting geometry and a modern integrated BIM wall. Wall tools place style-based straight or arc segments with width, height, offset, direction, and left/center/right justification. Existing lines, arcs, circles, and polylines can become walls; a mass element or ACIS solid can become a single-component wall, with an explicitly chosen baseline that later governs anchored inserts. [Wall command](https://help.autodesk.com/cloudhelp/2027/ENU/AutoCAD-Architecture/files/GUID-B4D64843-7D0C-47D1-B3D7-BA6A844AF0E7.htm), [linework/solid conversion](https://help.autodesk.com/cloudhelp/2027/ENU/AutoCAD-Architecture/files/GUID-F21A81B7-0E67-4201-BF9E-9DA79BF5FCB7.htm)

The wall style is the main reusable contract: it defines components, dimensions, materials, endcaps, display representations, and property data. Instance display and endcap overrides are allowed. Non-rectangular elevation is handled with editable/projected roof and floor lines; 3D body modifiers can add to, subtract from, or replace an individual wall component. Curtain walls are separate style-driven AEC objects with straight/curved paths and nested grids, divisions, cell infills, frames, and mullions. [Wall parameters](https://help.autodesk.com/cloudhelp/2027/ENU/AutoCAD-Architecture/files/GUID-9F548FE7-B70C-4C3B-9364-3ED676598A22.htm), [roof/floor lines](https://help.autodesk.com/cloudhelp/2027/ENU/AutoCAD-Architecture/files/GUID-AAD594E9-804F-47FD-A249-AF066A29B871.htm), [body modifiers](https://help.autodesk.com/cloudhelp/2027/CHT/AutoCAD-Architecture/files/GUID-E07C1DB6-DFC9-4DD8-BF67-9564C2CD441A.htm), [curtain walls](https://help.autodesk.com/cloudhelp/2027/ENU/AutoCAD-Architecture/files/GUID-05911682-63E7-4562-9902-543A350E595E.htm)

Its distinctive strength is cleanup control. Only walls in the same cleanup group interact; within that graph, component priority extends/trims matching components and subtracts higher-priority component profiles from lower-priority ones before inserts and hatching are applied. Doors, windows, and openings are anchored to walls, and wall styles control their opening endcaps. [Cleanup groups](https://help.autodesk.com/cloudhelp/2027/ENU/AutoCAD-Architecture/files/GUID-82455A71-8BA8-4307-A958-B452ED145235.htm), [cleanup algorithm](https://help.autodesk.com/cloudhelp/2027/ENU/AutoCAD-Architecture/files/GUID-A5F21978-FC03-4CFA-95F1-C027177A7A25.htm), [anchors](https://help.autodesk.com/cloudhelp/2027/ENU/AutoCAD-Architecture/files/GUID-2C2F7003-9D62-485F-A273-BDFB31A3E57F.htm)

Property sets and hierarchical classifications support schedules, display themes, construction status/project phase conventions, and IFC export. Project Navigator organizes a building as level/division-assigned construct DWGs assembled through Xrefs into views and sheets; this is file-based coordination rather than Revit/Archicad-style element worksharing or native design options. The product's .NET interfaces expose most Architecture/MEP database structures, with ObjectARX and the broader AutoCAD APIs available underneath. [Classifications](https://help.autodesk.com/cloudhelp/2027/ENU/AutoCAD-Architecture/files/GUID-708C0F2B-56F0-40C7-BBC9-6E3E208AC345.htm), [Project Navigator](https://help.autodesk.com/cloudhelp/2027/ENU/AutoCAD-Architecture/files/GUID-BDA8F9DF-B9C2-4014-B783-E12C9CAC90CD.htm), [constructs](https://help.autodesk.com/cloudhelp/2027/ENU/AutoCAD-Architecture/files/GUID-24051115-1562-42B1-B617-B2A54F61061F.htm), [Architecture/MEP API](https://aps.autodesk.com/developer/overview/autocad-architecture-and-mep)

### SketchUp 2026

SketchUp's native abstraction is deliberately geometric: every model is edges and faces. A wall is normally made by drawing or importing a footprint/profile, offsetting for thickness, and using Push/Pull or Follow Me; groups prevent wall geometry from sticking to neighboring geometry, while components provide shared definitions and reusable instances. Solid Tools provide union, subtract, trim, intersect, split, and outer-shell operations for closed groups/components. This makes arbitrary curved, slanted, tapered, and profiled forms easy, but there is no native wall path, wall type, compound-layer assembly, component-priority join, level constraint, stacked wall, or curtain-wall system in the documented core model. That last sentence is an inference from the official entity and modeling documentation, not a claim about third-party extensions. [Drawing model](https://help.sketchup.com/en/sketchup/drawing-lines-shapes-and-3d-objects), [groups](https://help.sketchup.com/en/sketchup/grouping-geometry), [components](https://help.sketchup.com/en/sketchup/components), [Solid Tools](https://help.sketchup.com/en/sketchup/modeling-complex-3d-shapes-solid-tools)

Openings likewise operate at the geometry level, except that a component can define a gluing plane and `Cut Opening` behavior so a door/window-like component cuts the face on which it is placed. Materials apply to faces or whole groups/components and can use PBR maps; material area is available, but distinct construction skins must be modeled and organized manually. Tags control visibility of groups/components rather than geometry topology. [Basic components](https://help.sketchup.com/en/sketchup/creating-basic-component), [materials](https://help.sketchup.com/en/sketchup/adding-colors-and-textures-materials), [tags](https://help.sketchup.com/en/sketchup/controlling-visibility-tags)

Semantic BIM is optional metadata layered onto groups/components. The Classifier can attach IFC types and attributes; Generate Report exports component attributes, quantities, and materials to CSV; the current importer/exporter supports IFC2x3 and IFC4, creates tags for IFC classes on import, and offers standard spatial hierarchy plus tessellated/body geometry on export. The Ruby API can build and transform all underlying geometry and metadata, so extensions can implement parametric walls, but the extension owns those behaviors. [Classifier](https://help.sketchup.com/en/sketchup/classifying-objects), [reports](https://help.sketchup.com/en/sketchup/generating-attribute-report), [IFC](https://help.sketchup.com/en/importing-and-exporting-ifc-files), [Ruby geometry](https://ruby.sketchup.com/file.generating_geometry.html)

### Rhino 8, Grasshopper, and Rhino.Inside.Revit

Native Rhino is also not an architectural wall system. It is a general geometry kernel whose relevant primitives are curves, extrusions, NURBS surfaces/polysurfaces (Breps), meshes, and SubD. A wall-like object can be a capped profile extrusion, a profile swept along any curve, a loft between changing sections, an offset/shell, or a Boolean result. Rhino's freedom exceeds every BIM wall type here, but inside/outside, construction layers, hosts, levels, phases, classifications, schedules, and wall joins exist only as user conventions, custom metadata, scripts, or plug-ins. [RhinoCommon namespaces](https://developer.rhino3d.com/api/rhinocommon), [ExtrudeCrv](https://docs.mcneel.com/rhino/8/help/en-us/commands/extrudecrv.htm), [Sweep1](https://docs.mcneel.com/rhino/8/help/en-us/commands/sweep1.htm)

Rhino offers object/layer materials, blocks, names, and user text; `Join` and Boolean commands solve geometric continuity rather than building-component cleanup. Command History can keep selected parent/child geometry associative, but direct child edits, joins, deleting parents, or some transforms can break the relationship. Grasshopper is the stronger parametric model: parameters and components form an explicit dependency network over Rhino and custom data types, and RhinoCommon exposes the geometry kernel to C#, Python, and plug-ins. [Object properties](https://docs.mcneel.com/rhino/8/help/en-us/properties/object.htm), [Join](https://docs.mcneel.com/rhino/8/help/en-us/commands/join.htm), [History](https://docs.mcneel.com/rhino/8/help/en-us/commands/history.htm), [Grasshopper algorithms/data](https://developer.rhino3d.com/guides/grasshopper/gh-algorithms-and-data-structures/)

Rhino.Inside.Revit is the important architectural bridge. It runs Rhino and Grasshopper inside Revit and supplies Revit-aware components that query Basic/Stacked/Curtain wall types and instances, analyze location curves, profiles, compound layers and inserts, and add native Revit walls by curve or profile. A Grasshopper parameter change can update the native Revit wall. The vendor explicitly distinguishes this from sending arbitrary Rhino solids as DirectShapes: DirectShape is fast and categorized, but Revit cannot resolve native interactions such as extending a wall to a DirectShape roof. [Rhino.Inside overview](https://www.rhino3d.com/inside/revit/1.0/), [wall workflow](https://www.rhino3d.com/inside/revit/1.0/guides/revit-walls), [interactive wall example](https://www.rhino3d.com/inside/revit/1.0/getting-started), [Rhino-to-Revit strategies](https://www.rhino3d.com/inside/revit/1.0/guides/rhino-to-revit)

### Graphisoft Archicad 29

Archicad's wall abstraction is closest to Revit's but with a broader set of plan geometries on the core tool. Walls may be straight, curved, chained, rectangular, trapezoidal, or polygonal. They carry a directional reference line: basic walls can reference outside/center/inside faces, while composites add outside/center/inside-of-core choices. The bottom is linked to a Home Story; the top may link to any story above with offsets, or use a fixed height. Wall forms include slanted and double-slanted, log, basic, composite, and custom complex-profile walls. Curtain Wall is deliberately a separate tool and schema. [Walls](https://help.graphisoft.com/AC/29/INT/_AC29_Help/040_ElementsVB/040_ElementsVB-6.htm), [wall settings/reference lines](https://help.graphisoft.com/AC/23/INT/_AC23_Help/140_UserInterfaceToolSettings/140_UserInterfaceToolSettings-3.htm)

Building Material is the key unifying attribute. A basic wall has one; a composite owns ordered skins with material, thickness, separator, and core/finish/other role; a complex profile is a reusable 2D cross-section of Building Material fills and may expose stretch/offset modifiers. Building Material intersection priority drives automatic associative junctions between walls and other construction elements, while Junction Order resolves equal-priority and multi-wall cases. Surface appearance comes from the Building Material but outside, inside, edge, or profile surfaces can be overridden per wall. [Composites](https://help.graphisoft.com/AC/29/INT/_AC29_Help/025_Attributes/025_Attributes-28.htm), [profiles](https://help.graphisoft.com/AC/29/INT/_AC29_Help/025_Attributes/025_Attributes-54.htm), [connections](https://help.graphisoft.com/AC/29/INT/_AC29_Help/040_ElementsVB/040_ElementsVB-269.htm)

Doors, Windows, and Wall Ends are parametric objects that require a wall host. The general Opening tool adds associated full- or limited-depth rectangular, circular, or polygonal holes; openings move with the host, can cut multiple elements, and carry IDs, classifications, properties, labels, and schedule data. Component schedules report net/gross volume and projected area with openings included or subtracted according to the requested quantity. [Walls](https://help.graphisoft.com/AC/29/INT/_AC29_Help/040_ElementsVB/040_ElementsVB-6.htm), [Openings](https://help.graphisoft.com/AC/29/INT/_AC29_Help/040_ElementsVB/040_ElementsVB-258.htm), [component schedule parameters](https://help.graphisoft.com/AC/29/INT/_AC29_Help/060_ElementParameters/060_ElementParameters-35.htm)

Archicad treats information and lifecycle as part of the same element model. Elements can hold one value per Classification System, and classification drives available properties, schedules, filters, structural function/position, and IFC type mapping. Renovation Status and view-saved Renovation Filters distinguish existing/new/demolished states; Design Option Sets assign elements to alternatives; BIMcloud Teamwork uses live element/data reservation, including automatic reservation where possible. [IFC classification](https://help.graphisoft.com/AC/29/INT/_AC29_Help/121_IFC/121_IFC-3.htm), [renovation filters](https://help.graphisoft.com/AC/29/INT/_AC29_Help/050_ViewsVB/050_ViewsVB-103.htm), [design options](https://help.graphisoft.com/AC/29/INT/_AC29_Help/071_DesignOptions/071_DesignOptions-4.htm), [Teamwork](https://help.graphisoft.com/AC/29/INT/_AC29_Help/080_Collaboration/080_Collaboration-25.htm)

The Archicad 29 C++ API exposes wall geometry/type fields, polygonal wall memos, reference-line modes, connections, wall quantities, doors/windows, openings, and the full separate curtain-wall decomposition. Elements receive stable GUIDs and can be created or modified through the same logical prerequisites as the UI—for example a host wall must exist before its door/window. The vendor's Grasshopper–Archicad Live Connection adds Wall Settings and wall design components, preserving native Archicad element output rather than baking anonymous solids. ## Implications for a repository-level comparison

1. **Keep an authoritative reference path and orientation.** Revit's Location Line, AutoCAD Architecture's baseline/justification, and Archicad's reference line all let width or assembly change without losing design alignment.
2. **Treat construction as ordered semantic components, not merely offset meshes.** The recurring fields are material, thickness, role/function, core membership, priority, and wrapping. Revit additionally demonstrates vertical regions and a variable layer; Archicad demonstrates profile fills and modifiers.
3. **Make joins a solver with inspectable policy.** Revit offers join type/order, AutoCAD Architecture adds cleanup groups plus component overrides, and Archicad combines material priority with junction order. Geometry contact alone is insufficient once layers and edits matter.
4. **Represent openings and hosted elements explicitly.** A robust host relationship must preserve relative placement, create the cut, participate in layer wrapping/cleanup, survive wall edits, and report both the child and net host quantities.
5. **Separate ordinary walls from specialized envelopes without losing common identity.** Revit keeps Basic/Stacked/Curtain under `Wall`; Archicad and AutoCAD Architecture use separate curtain-wall schemas. Either can work if common selection, classification, material, schedule, and host contracts remain shared.
6. **Store design intent separately from solved geometry.** Slants, tapers, profile edits, attachments, joins, and openings should regenerate derived solids. SketchUp and Rhino show the flexibility of direct geometry; their tradeoff is that semantic regeneration and downstream documentation become extension responsibilities.
7. **Plan information and lifecycle early.** Classification/IFC mapping, net/gross/component quantities, phase or renovation status, option membership, and collaboration ownership are not presentation-only metadata in the BIM products; they affect visibility, export, schedules, and edit permissions.
8. **Let automation create native wall intent.** The successful Grasshopper bridges pass paths/profiles plus type, level/story, and settings into the host wall API. Direct-shape exchange remains valuable as an explicit fallback, not the default representation for editable architectural walls.
