# Next stair improvements

Research checked 2026-10-06 against the [completed implementation ledger](stair-implementation-progress.md) and current stair schemas/helpers. The table records gaps at the research date; implementation status is recorded below. Straight/L/U presets, curved and signed multi-turn spiral stairs, five construction modes, six guard styles, separate handrails, walking lines, sizing/headroom diagnostics and semantic IFC export already exist.

| Priority | Improvement | Verified current gap and proposed result |
| --- | --- | --- |
| 1 | Handrail endings and accessible grip | The independent handrail schema has only side mode, height, diameter and offset. Add separate top horizontal and bottom sloped extensions, wall/post/floor returns, wall clearance and optionally a second handrail. Existing guard `railingTopReach` is a sloped top guard reach, not independent handrail ending control. The Access Board documents continuity, extensions, returns and gripping clearance; Autodesk exposes dedicated rail extension controls. [Access Board stair guide](https://www.access-board.gov/aba/guides/chapter-5-stairways/), [Revit extensions](https://help.autodesk.com/cloudhelp/2022/ENU/Revit-HaveYouTried/files/GUID-5DDAC1B5-04C1-416A-8F45-C6FFCEB483CA.htm) |
| 2 | Real L/U winders and editable walking line | Child segments currently distinguish only flights and landings; arc stairs have uniform radial divisions. Add explicit quarter/half-turn winder segments, equal-going/equal-angle strategies, walking-line offset and inner-tread measurements. A spiral already exists and should not be advertised as a missing feature. Graphisoft supports both winder types and a walking-line offset affecting tread geometry. [Segment types](https://help.graphisoft.com/AC/28/INT/_AC28_Help/040_ElementsVB/040_ElementsVB-183.htm), [Winder creation](https://support.graphisoft.com/hc/en-us/articles/28036068326929-How-can-I-create-a-stair-with-two-winders-turning-in-opposite-directions), [Walking-line settings](https://helpcenter.graphisoft.com/user-guide/128189/) |
| 3 | Named design-use profiles and transparent diagnostics | Existing targets cover maximum riser, minimum/target going and headroom. Add purpose and jurisdiction/version metadata plus checks for handrail geometry, closed risers, nosing profile and wet-use intent. Keep findings separate from a blanket compliance claim. For example, the US ADA standards address uniform treads/risers, nosings, handrails and preventing water accumulation, with specific scoping. [ADA standards §§504–505](https://www.access-board.gov/ada/) |
| 4 | Repeated multi-storey stair assemblies | Current stairs connect one source and destination; the ledger explicitly defers repetition. Add selected-level replication, shared edits for equal-height storeys, independent exceptions for differing storey heights, and coordinated guards/openings. Revit models grouped equal-height stairs and individual exceptions. [Revit multistory API](https://help.autodesk.com/cloudhelp/2024/ENU/Revit-API/files/Revit_API_Developers_Guide/Revit_Geometric_Elements/Stairs_and_Railings/Revit_API_Revit_API_Developers_Guide_Revit_Geometric_Elements_Stairs_and_Railings_Creating_and_Editing_Stairs_html.html) |
| 5 | Editable guard components and transition details | Six visual styles exist, but stair-level style selection offers little component authoring. Add configurable post distribution, panel spans, infill spacing, profiles, bracket/mount details and per-boundary overrides; extend guards into adjoining landing/opening edges. Graphisoft exposes posts, balusters, rails and panels as editable components. This is an authoring-fidelity improvement, not proof that current styles fail a particular rule. [Railing component edit mode](https://help.graphisoft.com/AC/28/INT/_AC28_Help/040_ElementsVB/040_ElementsVB-210.htm) |
| 6 | Construction joints and connection details | Existing solid/waist/open/stringer modes provide bodies and finish dimensions. Add authored flight-start/end cuts, bearing nibs, flight/landing joints and support/mount semantics. Graphisoft exposes different connections within one stair. [Stair endings and connections](https://help.graphisoft.com/AC/29/INT/_AC29_Help/040_ElementsVB/040_ElementsVB-199.htm) |

Broader headroom obstruction coverage is also needed: the current ledger explicitly limits queries to slabs, ceilings and stair bodies. Extend the same shared query to roofs, imported bodies and other relevant obstructions, while showing unresolved coverage honestly. This is a repository-derived gap rather than an externally mandated obstacle classification.

After the geometric work, investigate stair documentation: level-specific up/down arrows, riser numbering, cut-height break marks and hidden-above line styles. Graphisoft supports these presentation controls. Our existing walking line and 2D/3D geometry parity should remain the foundation. This presentation recommendation needs a complete plan/export audit before declaring each control absent. [Graphisoft floor-plan settings](https://help.graphisoft.com/AC/29/INT/_AC29_Help/040_ElementsVB/040_ElementsVB-202.htm)

Useful future presets include architectural/public circulation, compact residential, exterior/deck and repeated egress stairs. These should select editable geometry and clearly scoped guidance rather than attach one universal rule set. Branched monumental stairs, arbitrary mixed curved/straight paths, cantilever support details and service ladders are later product-scope choices; they should not distract from handrail endings, winders and safer diagnostics first.

Evidence inspected: `packages/core/src/schema/nodes/stair.ts`, `stair-segment.ts`, `stair-construction.ts`; `packages/core/src/systems/stair/stair-presets.ts`, `stair-walking-line.ts`, `stair-rail-path.ts`, `stair-sizing.ts`; implementation ledger. No implementation changes or new tests were made for this research. Accessibility examples above are scoped US guidance, not universal rules or a structural engineering assessment.

Implementation update: independent handrail extensions and geometric wall/post/floor returns, plus L/U winders with both division strategies and walking-line offsets, are implemented and independently reviewed. See the [implementation ledger](stair-implementation-progress.md) for verification and limits. Wall hosting/clearance, a second handrail, and the remaining recommendations are still future work.
